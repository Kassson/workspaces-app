# Workspaces

Веб-приложение для колледжа: группы (пространства), расписание, домашние
задания со сдачей фото, журнал оценок с Excel-импортом/экспортом, чат,
игровой центр и система уведомлений.

Клиент — обычные HTML/CSS/JS без сборки. Сервер — Node.js + Express +
Socket.IO + PostgreSQL.

## Быстрый старт локально

```bash
npm ci
cp .env.example .env      # заполните JWT_SECRET и ROOT_TEACHER_PASSWORD
npm start                 # http://localhost:3000
```

Схема БД создаётся и обновляется автоматически при старте (`schema.sql`).
Нужен доступный PostgreSQL, строка подключения — в `DATABASE_URL`.

Вход администратора: логин `root_teacher`, пароль из `ROOT_TEACHER_PASSWORD`.

## Проверки

```bash
npm test              # всё сразу
npm run test:api      # 63 теста HTTP/Socket API на поддельной БД
npm run test:static   # обработчики, id, версии ассетов, PWA
npm run test:encoding # кодировка файлов (UTF-8 без BOM)
```

Тесты API работают без реального PostgreSQL: драйвер `pg` подменяется
маршрутизатором SQL над таблицами в памяти (`test-mock-pg.js`). Это проверяет
логику приложения и права доступа, но **не** сам PostgreSQL — на боевой базе
стоит один раз убедиться, что `npm start` применил схему без ошибок.

## Роли

- **Ученик** — расписание, ДЗ (сдача фото), свой журнал, чат, игры.
- **Преподаватель** (`is_teacher` + `is_teacher_verified`) — доступ ко всем
  группам, ведение журнала, управление участниками.
- **Админ группы** (`role` = `admin` / `starosta`) — управление участниками
  своей группы, если это разрешено настройкой `members_can_manage`.
- **root_teacher** — главный администратор: глобальные настройки, удаление
  групп, скрытие учеников из журнала.

## Настройки группы

Преподаватель задаёт в разделе «Настройки» → «Настройки группы»:

- название группы;
- доступные разделы: расписание, ДЗ, журнал, чат, игры, файлы
  (выключенный раздел скрывается у всех и блокируется на сервере);
- кто может добавлять ДЗ (`admins` / все участники) и отмечать сдачу;
- права участников: список участников, отправка в чат, реакции, удаление
  своего ДЗ, обмен оценками, просмотр чужих оценок;
- права админов группы (полное управление / только просмотр).

Изменения применяются мгновенно у всех участников через websocket.

## Хранилище файлов

- Если заданы `YC_ACCESS_KEY_ID`, `YC_SECRET_ACCESS_KEY`, `YC_BUCKET_NAME` —
  файлы идут в Yandex Object Storage, ссылки подписываются на 24 часа.
- Иначе включается локальный режим: файлы пишутся в `LOCAL_UPLOAD_DIR` и
  раздаются через `/api/local-files/*`.

В базе хранятся **ключи** объектов, а не ссылки: подписанные ссылки истекают,
поэтому они генерируются заново при каждом чтении.
